# 설계 원칙 (적용 요약)

> 원문: [`docs/world/world-design-principles.md`](../../world/world-design-principles.md) — 이 요약보다 원문이 우선한다.
> 지위: 세계 설계의 **원칙** (WB-0002). 세계의 사실이 아니라 설정을 만드는 방법이다.

## 핵심 방향

정해진 최종 목표를 따라가는 구조보다, 세계를 탐험하며 정보·관계·사건을 발견하고 스스로 목표를 형성하는
구조를 우선한다 (**상태 기반 세계 시뮬레이션 + 발견형 목표 생성**, `source-analysis.md`).

## World Bible 항목이 갖추어야 할 것

| 대상 | 최소 요소 (원문 §) |
|---|---|
| 지역 | 지형·기후, 주민·종족, 경제·자원, 시설, 직업, 위험, 갈등, 비밀, 이동 경로, 역사 (§1) |
| NPC | 역할, 개인 목표, 일정, 과거, 관계, 약점, 소속, 현재 상태 — 플레이어를 기다리는 퀘스트 제공자가 아니다 (§2) |
| 조직 | 목표, 자원, 영향력, 내부 구조, 우호·적대, 행동 조건 (§3) |
| 경제 | 통화, 지역별 가격, 자원 분포, 생산, 무역, 수송 — 희소성이 이동과 교역의 이유가 된다 (§4) |
| 능력 | 습득 조건, 수련 비용, 희소성, 스승·전승, 사회적 가치, 연계 장비 — 사회 구조와 연결된다 (§5) |
| 사건 | Trigger → Event → Consequence (§6) |
| 목표 | 의뢰·소문·계약·탐험·우연·욕구·후속 결과 등 여러 경로 (§7) |
| 정보 | 출처와 신뢰도. 같은 사건도 출처마다 다르다 (§8) |
| 아이템 | 제작자·시기·소유자·사건·전승 — 역사적 객체 (§9) |
| 역사 | 현재 상태는 과거 사건의 결과다 (§10) |

## 연결망 원칙 (§11)

새 설정은 최소 하나 이상의 기존 요소와 연결한다. 예: 지역 → 종족 → NPC → 신앙 → 아이템 → 사건 → 조직 → 역사.

## 우선순위 (§12)

1. 플레이어 자율성 2. NPC 독립성 3. 사건의 인과성 4. 설정 간 연결성 5. 구현 가능한 복잡도 6. 데이터로 관리 가능한 구조

원작에서 추출한 원칙은 참고하되 특정 원작의 고유 설정을 그대로 복제하지 않는다.
