# Phase 236–250 — 실행 가능한 분기 사건 코어

## 개발 목표
Phase 221–235에서 문서화된 분기형 사건 구조를 실제 브라우저 실행 코드로 내려, 세계 상태 → 사건 생성 → 선택 → 판정 → 결과 반영의 최소 폐루프를 확보했습니다.

## 구현
- `web/index.html` 실행 진입점 추가
- `web/styles.css` TXT RPG 전용 반응형 UI 추가
- `web/game.js` 게임 상태·시간·이동·조사·NPC 대화·저장 계층 구현
- `anonymous_chronicles_save_v2` 저장 키 사용
- 곡물 창고 / 야간 화물 / 토지 기록의 3개 분기 사건 구현
- 사건별 3개 선택지와 위험도 도입
- 사건 선택은 `caseId + choiceId + day` 기반 결정론적 1~6 판정
- 성공 시 사건 해결, 실패 시 긴장도 상승 및 반복 실패 시 사건 실패
- 결과가 곡물 공급, 돈, 치안, 행정 신뢰, 긴장도, 발견 정보에 반영
- 기존 세이브의 배열 기반 `cases` 누락을 빈 배열로 복구하도록 방어

## 명령
- `사건목록` — 현재 열린 사건 목록
- `사건분기 1` — 첫 번째 열린 사건의 선택지 확인
- `사건분기 1 2` — 두 번째 선택지 실행
- 사건 ID 직접 지정도 지원: `사건분기 grain-warehouse 1`

## 구조적 판단
이번 단계에서는 IndexedDB/Web Worker를 억지로 추가하지 않고, 먼저 브라우저에서 실제로 실행되는 작은 코어를 확보했습니다. 다음 단계에서는 현재 `state.world`와 사건 정의를 데이터 계층으로 분리한 뒤 IndexedDB 저장 및 Worker 시뮬레이션을 연결하는 것이 통합 위험이 가장 낮습니다.
