# 개발 가속 방안 (2026-10-12)

> **지위**: V2 개발의 *운영 방식*이다.
> - `AGENTS.md`와 `DEVELOPMENT_RULES.md`의 규칙(검증 생략 금지, Hard Gate, V1 경계)은 바꾸지 않는다.
> - §5의 항목은 소유자 결정이 필요하다. 승인 전까지 적용하지 않는다.
>
> **로드맵**: 게임 완결까지의 마일스톤은 World Bible `00-governance/roadmap.md`(`docs/world-bible` 브랜치)에 있다. 이 문서는 그 로드맵을 *어떻게* 빨리 가는가를 다룬다.

## 1. 진단 — 무엇이 느리게 하는가

속도는 검증을 줄여서 얻지 않는다. 기다림, 왕복, 중복을 줄여서 얻는다. 아래 근거는 GitHub의 PR·CI 기록과 저장소에서 2026-10-12에 확인했다.

| # | 병목 | 근거 | 영향 |
|---|---|---|---|
| 1 | **방향 결정 대기** | World Bible `roadmap.md`의 종료 평가 다섯 곳이 "다음 Master Goal: 소유자의 선택을 기다린다"로 끝난다. 완결 조건 중 서사(GMG-02), 최강자의 증명(GMG-03.3), 출시(GMG-07)는 미착수·보류다. 모두 R-1 ~ R-5와 소유자 보류 축(WB-0018 §4)에 막혀 있다 | **속도를 올려도 게임이 완결되지 않는다.** 가장 큰 병목이다 |

## 2. 원칙

1. **완결 조건에 닿는 일을 먼저 한다.** SGMG-01의 일곱 조건(master-goals §1.2)이 기준이다. 시스템을 더 깊게 만드는 일은 완결 조건의 빈칸을 채울 때만 우선한다.
2. **결정은 묶어서 한 번에 묻는다.** 방향이 막히면 기다리지 않는다. 결정 대기열에 넣고, 막히지 않은 다음 일을 한다.
3. **검증은 줄이지 않고 자동화한다.** 품질 게이트(RED → GREEN → REFACTOR → VERIFY → DECIDE)는 그대로다. 사람이 하던 단계를 한 명령으로 바꾼다.
4. **한 가지 사실은 한 곳에만 쓴다.**

## 4. 운영 규칙 (지금부터, 소유자 결정 없이 적용)

### 4.1 변경 등급 (Lane)

| Lane | 무엇 | 필수 검증 | 사전 등록 측정 |
|---|---|---|---|
| **A** | 문서, 테스트, 도구, UI 문구. 게임 상태는 바뀌지 않는다 | `verify.sh quick` + 관련 브라우저 spec | 없음 |
| **B** | 기존 시스템 안의 콘텐츠와 데이터. 가산적이고 경제 값과 저장 의미는 그대로다 | `verify.sh full`, 해당하면 `campaign.sh escort-parity`·`trade-parity`, 데이터 변이 테스트 | 판단이 결과에 달린 경우만 |
| **C** | 경제 값, 정보 정확도 목표, 엔진·State·Save, Canon | `verify.sh full` + 사전 등록 측정 + Hard Gate면 소유자 결정 | 필수 |

등급이 애매하면 높은 쪽으로 본다.

### 4.2 작업 단위

- **MG 하나 = 브랜치 하나 = PR 하나.** 단계는 PR 안의 커밋으로 나눈다.
  - 나누는 경우: Lane C, 또는 되돌릴 단위를 분리해야 할 때.
- **World Bible 기록은 마일스톤마다 PR 하나로 묶는다.** 게임과 World Bible의 작업선은 계속 분리한다.
- **열차(stacked).** 다음 MG는 아직 열린 PR 위에서 시작한다. 승인은 열차 단위로 묶어 받는다. 앞 PR이 거절되면 그 위의 PR을 다시 기반에 올린다(rebase가 아니라 merge).

### 4.3 측정의 시간 상자

- Lane C 측정은 **설계 1회와 재설계 1회까지**다.
- 같은 기준에서 두 번 실패하면 데이터를 더 조정하지 않는다(AGENTS.md DECIDE). 가설을 고치거나 결정 대기열로 넘긴다. 다음 MG는 막지 않는다.
- 측정은 `campaign.sh`의 고정 캠페인을 먼저 쓴다. 새 측정기는 고정 캠페인으로 답할 수 없을 때만 만든다.

### 4.4 결정 대기열

- 소유자 결정이 필요한 항목은 World Bible `roadmap.md`의 "결정 대기열"에 **권고안과 함께** 넣는다.
- 결정을 기다리는 동안 막히지 않은 다음 일을 한다.
- MG 종료 평가는 "소유자의 선택을 기다린다"로 끝내지 않는다. 막히지 않은 다음 후보를 하나 고른다.

### 4.5 한 곳 원칙 (문서)

| 무엇 | 어디에 |
|---|---|
| 진행 상태 | World Bible `roadmap.md` 마일스톤 표 |
| 엔진·데이터 계약 | `CORE_CONTRACTS.md` D행. 계약이 바뀔 때만 쓴다. 작업 로그는 한 줄 |
| 측정 설계와 결과 | 설계 문서. Lane C만 쓴다 |
| 정본·Provisional 기록 | World Bible `canon-review/` |
| MG 상태 | `master-goals.md`. 마일스톤이 끝날 때 한 번 고친다 |
| PR 본문 | 요약, 검증(실행한 것만), Lane, Canon·Save 영향, 결정 필요, 링크. 결과를 다시 서술하지 않는다 |

### 4.6 PR 본문 형식

```
## 무엇을 왜 (Lane A/B/C, MG·마일스톤)
## 변경
## 검증 — verify.sh 요약 그대로, campaign.sh 결과(해당 시)
## Canon·Save·경제 값 영향
## 결정 필요 (없으면 "없음")
```

## 5. 소유자 결정이 필요한 가속 (적용하지 않음)

| # | 제안 | 근거 | 권고 |
|---|---|---|---|
| P1 | **병합 권한.** 지금은 "승인 없는 PR 병합을 하지 않는다"(소유자 지시)가 적용된다. WB-0018의 원래 위임은 "Hard Gate가 아닌 작업은 승인을 기다리지 않는다"였다 | §1의 2 | Lane A·B는 게이트(로컬 `verify.sh full` + CI 녹색 + 해당 parity)를 통과하면 자율 병합한다. Lane C, Hard Gate, Canon은 승인을 받는다. 또는 마일스톤마다 한 번 조건부로 승인한다 |
